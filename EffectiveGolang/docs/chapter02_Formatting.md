# Chapter 02. Formatting

> 원문: [Effective Go — Formatting](https://go.dev/doc/effective_go#formatting)

---

## 1. 핵심 철학: "스타일은 기계가 결정한다"

원문은 포매팅을 이렇게 규정한다.

> Formatting issues are the most **contentious** but the **least consequential**.

포매팅은 가장 논쟁적이지만 가장 덜 중요한 문제다. 사람은 어떤 스타일에도 적응할 수 있지만, **모두가 같은 스타일을 따르면 그 적응조차 필요 없고 스타일 논쟁에 쓰는 시간도 사라진다.** 문제는 "긴 규범적 스타일 가이드(prescriptive style guide) 없이" 어떻게 이 이상향에 도달하느냐다.

Go의 답은 독특하다. **기계가 대부분의 포매팅을 처리하게 한다.** 그 기계가 `gofmt`다.

전문가 관점에서 이것이 갖는 의미:

- 스타일은 **토론·리뷰 대상이 아니다.** PR 리뷰에서 들여쓰기·정렬·중괄호 위치를 지적할 일이 없어진다 → 사람은 **로직과 설계에만 집중**한다.
- 모든 Go 코드베이스가 시각적으로 동일해, **남의 코드를 읽는 비용**이 극적으로 낮아진다. 표준 라이브러리 전체가 `gofmt`로 포매팅되어 있다.

---

## 2. gofmt — 작동 방식과 사용 원칙

`gofmt` 프로그램(`go fmt`로도 호출 가능)은 Go 소스를 읽어 **표준 스타일의 들여쓰기와 수직 정렬(vertical alignment)**로 다시 출력하며, 주석은 보존하되 필요하면 재정렬한다.

> 참고: `gofmt`는 **파일 단위**, `go fmt`는 **패키지 단위**로 동작한다.

원문이 제시하는 황금률:

> 새로운 레이아웃 상황을 어떻게 다룰지 모르겠으면 **`gofmt`를 돌려라.** 결과가 이상해 보이면 **프로그램을 재배치하라(또는 gofmt 버그를 신고하라). 절대 우회(work around)하지 마라.**

즉 포매팅에 대한 "내 의견"을 갖지 않는 것이 관용구다. 도구의 출력이 곧 정답이다.

### 예: 구조체 필드 주석 정렬

필드 주석을 손으로 줄 맞출 필요가 없다. 다음 선언을 주면

```go
type T struct {
    name string // name of the object
    value int // its value
}
```

`gofmt`가 열을 자동 정렬한다.

```go
type T struct {
    name  string // name of the object
    value int    // its value
}
```

## 3. 남아 있는 포매팅 세부 규칙

`gofmt`가 대부분을 처리하지만, 알아두면 좋은 몇 가지 규칙이 있다.

### 들여쓰기(Indentation) — 탭 사용

들여쓰기는 **탭(tab)**을 쓰며 `gofmt`가 기본으로 탭을 출력한다. **꼭 필요할 때만** 스페이스를 쓴다.

> 실무 함의: 탭이므로 개발자는 편집기에서 탭 폭을 자유롭게 설정해 볼 수 있다(누군가는 4, 누군가는 8). 정렬이 깨지지 않는다.

### 줄 길이(Line length) — 제한 없음

Go에는 **줄 길이 제한이 없다.** "펀치 카드(punched card) 넘칠 걱정"을 하지 말라는 표현이 그대로 쓰여 있다. 줄이 너무 길게 느껴지면 줄을 나누고 **추가 탭 하나로 들여쓰기(wrap & indent)** 하면 된다.

### 괄호(Parentheses) — 더 적게

Go는 C/Java보다 괄호가 적게 필요하다.

- **제어 구조(`if`, `for`, `switch`)는 문법상 괄호를 쓰지 않는다.**
- **연산자 우선순위 계층(operator precedence hierarchy)이 더 짧고 명확**하다.

그래서 다음 표현은

```go
x<<8 + y<<16
```

**띄어쓰기가 암시하는 그대로** 해석된다. C/Java와 달리 의미가 모호하지 않다.

> 해설: Go에서 시프트(`<<`)는 곱셈·덧셈 등과 우선순위가 정리되어 있어, `(x<<8) + (y<<16)`로 의도대로 묶인다. 공백을 우선순위 힌트처럼 활용하는 관용도 여기서 나온다 — 우선순위가 높은 연산은 붙이고(`x<<8`), 낮은 연산 주위는 띄운다(` + `).

---

## 4. 정리

| 항목 | 규칙 |
|---|---|
| 스타일 결정 주체 | 사람이 아니라 **`gofmt`** (논쟁·우회 금지) |
| 들여쓰기 | **탭**, 스페이스는 불가피할 때만 |
| 줄 길이 | **제한 없음**, 길면 나누고 추가 탭 들여쓰기 |
| 제어 구조 괄호 | `if`/`for`/`switch`에 괄호 **없음** |
| 연산자 우선순위 | C/Java보다 짧고 명확 → 괄호가 덜 필요, 공백으로 의도 표현 |
| 구조체 필드 주석 | 손으로 정렬하지 말 것 — `gofmt`가 열 정렬 |

**한 줄 요약:** 포매팅에 대한 의견을 갖지 말고 `gofmt`를 신뢰하라. 이것이 Go 코드베이스 전체의 일관성과 낮은 가독성 비용을 만든다.
