# Chapter 05. Semicolons

> 원문: [Effective Go — Semicolons](https://go.dev/doc/effective_go#semicolons)

---

## 1. 세미콜론은 있지만 보이지 않는다

C처럼 Go의 **형식 문법(formal grammar)도 세미콜론으로 문장을 종료**한다. 그러나 C와 달리 **그 세미콜론은 소스 코드에 나타나지 않는다.** 대신 **렉서(lexer)가 스캔하면서 간단한 규칙으로 세미콜론을 자동 삽입(automatic semicolon insertion)**한다. 그래서 입력 텍스트는 대부분 세미콜론이 없다.

즉 Go에서 세미콜론을 거의 안 쓰는 것은 "문법에 없어서"가 아니라 **"렉서가 대신 넣어주기 때문"**이다. 이 차이를 이해해야 뒤에 나오는 중괄호 규칙이 납득된다.

---

## 2. 세미콜론 자동 삽입 규칙

> **개행(newline) 직전의 마지막 토큰이 다음 중 하나면, 렉서는 그 토큰 뒤에 세미콜론을 삽입한다.**

- **식별자(identifier)** — `int`, `float64` 같은 단어 포함
- **기본 리터럴(basic literal)** — 숫자나 문자열 상수 등
- 다음 토큰 중 하나:

  ```
  break   continue   fallthrough   return   ++   --   )   }
  ```

한 줄 요약: **"문장을 끝낼 수 있는 토큰 뒤에 개행이 오면 세미콜론을 넣는다."**

추가로, **닫는 중괄호 `}` 바로 앞에서는 세미콜론을 생략**할 수 있다. 그래서 다음 한 줄은 세미콜론이 전혀 필요 없다.

```go
go func() { for { dst <- <-src } }()
```

### 세미콜론을 직접 써야 하는 곳

관용적 Go 코드에서 세미콜론이 등장하는 곳은 사실상 두 군데뿐이다.

1. **`for` 루프 절** — 초기화(initializer)·조건(condition)·증감(continuation)을 구분할 때

   ```go
   for i := 0; i < n; i++ { ... }
   ```

2. **한 줄에 여러 문장**을 쓸 때 (그렇게 코드를 쓴다면)

   ```go
   x := 1; y := 2; z := 3
   ```

## 3. 가장 중요한 결과: 여는 중괄호는 같은 줄에

세미콜론 자동 삽입 규칙의 **핵심 귀결(consequence)**:

> 제어 구조(`if`, `for`, `switch`, `select`)의 **여는 중괄호 `{`를 다음 줄에 둘 수 없다.**

만약 다음 줄에 두면, 렉서가 **중괄호 앞에 세미콜론을 삽입**해 의도치 않은 동작을 일으킨다.

### 올바른 형태

```go
if i < f() {
    g()
}
```

### 잘못된 형태 (컴파일 에러)

```go
if i < f()   // wrong! — f() 뒤(개행 직전 마지막 토큰이 `)`)에 세미콜론이 삽입됨
{            // wrong! — 따라서 if 문이 여기서 끊기고, 이건 별개의 블록이 되어버림
    g()
}
```

`f()`의 `)`가 "문장을 끝낼 수 있는 토큰"이라 그 뒤에 세미콜론이 자동으로 들어간다. 결과적으로 `if i < f();`로 해석되어 컴파일이 깨진다.

> 그래서 Go는 K&R 스타일(여는 중괄호를 같은 줄에)을 **강제**한다 — 취향이 아니라 **렉서 규칙의 필연적 결과**다. Allman 스타일(중괄호를 다음 줄에)은 언어 차원에서 불가능하다.

## 4. 정리

| 항목 | 내용 |
|---|---|
| 세미콜론 | 문법엔 있으나 소스엔 안 보임 — **렉서가 자동 삽입** |
| 삽입 조건 | 개행 직전 토큰이 식별자/리터럴/`break continue fallthrough return ++ -- ) }` |
| `}` 앞 | 세미콜론 생략 가능 |
| 직접 쓰는 곳 | `for` 절 구분, 한 줄 다중 문장 |
| 여는 중괄호 | **반드시 같은 줄** — 다음 줄에 두면 세미콜론 자동 삽입으로 깨짐 |

**한 줄 요약:** Go는 세미콜론을 렉서가 자동으로 넣어준다. 이 규칙 때문에 제어 구조의 여는 중괄호는 반드시 같은 줄에 와야 하며, 이는 스타일 선택이 아니라 언어 차원의 강제다.
